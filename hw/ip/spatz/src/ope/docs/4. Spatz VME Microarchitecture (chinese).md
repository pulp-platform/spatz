# 4. Spatz VME 微架構

## VME 實作總覽

### 解碼與執行派送

Spatz VME 在既有 RVV 執行模型上加入矩陣狀態、矩陣操作與 tile 儲存。解碼器辨識 VME request 後依操作類別派送：矩陣設定操作由 controller 處理；矩陣 multiply-accumulate 與 tile subset move 送至 OPE；tile subset memory operation 送至 VLSU。每個向量或矩陣操作都取得共用 instruction identifier，使 controller 能在 VAU、OPE、VLSU 間一致追蹤相依性與 retirement。

### 執行單元：VAU、OPE 與 VLSU

VAU 執行一般 RVV 算術。OPE 執行分散式矩陣算術、管理 accumulator array，並在 accumulator 與 VRF 間搬移 tile subset。VLSU 執行 vector-memory 與 tile-memory transfer、產生記憶體位址，並處理記憶體端反壓。Tile subset memory operation 直接使用 VLSU–accumulator Tile path，不需經過 VRF。

### 共用 VRF 存取與 VAU–OPE 仲裁

VAU 與 OPE 在 Spatz top level 透過仲裁共用 VRF port。VRF 有三個 256-bit read port 與一個 256-bit write port。前兩個 read port 構成 atomic operand pair，分別供 VAU 的兩個向量來源，或 OPE MAC 的左右運算元使用；round-robin arbiter 每 cycle 將此 pair 授予 VAU 或 OPE。第三個 read port 獨立仲裁，供需讀目的向量的操作使用，例如 vector-to-tile move。唯一 write port 同樣由 VAU 與 OPE round-robin 共用。VLSU 的 vector-memory transfer 保留獨立 VRF-side interface，不是此 VAU–OPE shared-port arbiter 的 requester。

### Accumulator Tile 介面

Accumulator 連接兩個領域。內部的 FPU array 經 addend-read 與 result-writeback path 存取 lane-local accumulator bank；外部的 OPE 提供 VRF-facing path 以進行 tile subset move，VLSU 則經 Tile interface 執行 tile subset memory operation。Tile interface 一次傳輸一個 physical accumulator row，其硬體寬度為 TE × Accumulator Element Width：TE=16 為 512 bit，TE=32 為 1024 bit；可達吞吐量最終受 512-bit L1 data path 限制。這讓 memory transfer 可獨立於共用 VAU–OPE VRF port 存取 tile。

### 操作生命週期：相依性、完成與 retirement

Controller 維護矩陣設定，在 issue 時擷取操作所需設定，並以共用 instruction identifier 的 scoreboard 追蹤 vector-register 與 matrix-tile dependency。VME 操作可先進入 OPE 或 VLSU queue，尚未具備執行資格；只有滿足架構來源、目的與排序限制時，controller 才允許執行。OPE 與 VLSU 以 response interface 回報 local completion，controller 隨後更新相依狀態並 retire 該 identifier。解碼、queueing、issue、執行、local completion、retirement 的分離使 VME 可容忍本地 FPU、VRF、accumulator 與記憶體反壓，而不破壞 RVV 或 VME 排序語意。

## Controller

Controller 是 Spatz 向量與矩陣執行子系統的中央協調點，負責解碼並維護 matrix configuration、分配 common instruction identifier、追蹤 vector/tile dependency，並 retire 完成的 RVV、VME 操作。它不屬於 OPE wrapper，而是 VAU、OPE、VLSU 共用的全域排序機制。

### 矩陣設定狀態

VME matrix-configuration operation 由 controller 直接解碼與執行，設定後續 VME 操作所需的 element width（SEW）、tile element width（TEW）、widen 關係、active tile dimension（tn、tm）與 reduction extent（tk）。Matrix configuration 限制 vector grouping（lmul）、vector length（vl）與合法 tile dimension，因此 controller 會和 RVV vector configuration 一併維護它。

Matrix type configuration 決定 SEW、TEW 的關係與合法 matrix vector grouping。Controller 會將 tm、tn、tk 限制在 tile edge（TE）、vector-register grouping 與支援 reduction extent 的範圍；tn 由 vl 衍生，tm、tk 則獨立設定。後續 RVV vector-configuration operation 會使目前 matrix configuration（mtype CSR）失效，軟體須重新建立有效設定後才可 issue 下一個 matrix operation。

每個 issued VME request 都攜帶所需的 matrix/vector configuration。因此即使軟體其後改變架構設定，已緩衝在 OPE 或 VLSU 中的操作仍按 issue 時有效的設定解讀。

### Instruction identifier 與 vector scoreboard

Controller 為每個 issued RVV 或 VME operation 分配 common instruction identifier。實作最多支援八個 issued 但尚未 retired 的向量或矩陣操作；它們可能位於 execution-unit queue、VAU datapath、OPE FPU pipeline、accumulator access path、VLSU request queue 或 VRF writeback path。

Identifier 將接受的操作與 operand/destination dependency、execution-enable、completion response 及 retirement 關聯，使不同 functional unit 和 physical storage structure 上的 vector、matrix 操作仍能位於同一 dependency domain。

Controller 為 VRF 維護 read/write table，記錄每個 vector-register group 最年輕的 in-flight reader/writer。新操作 issue 時，controller 由 explicit source、destination、vector-register group size 與操作類型推導 dependency，記錄 instruction identifier 間的 RAW、WAR、WAW edge。VME scoreboard 追蹤完整架構 source footprint，不只追蹤特定 datapath 實際讀到的 vector。這對 packed-pair FP16-to-FP32 很重要：SDOTP datapath 從 packed base vector 實體取得兩個 reduction position，但 VME operand 定義仍包含 implicit row-stride source vector；controller 因此仍在 read table 中記錄這些 group，以保留架構 RAW 語意。

Scoreboard 也控制 VRF port access。操作可先進 local request queue，但只有相關 scoreboard condition 滿足後，才能真正存取 VRF port。

### Matrix tile scoreboard

Controller 對 in-flight tile operation 維護 matrix dependency state。每個矩陣操作記錄 target tile subset、是否讀/寫 accumulator state，以及由 OPE 或 VLSU 執行。Tile subset 以 architecture tile region 的 mask 表示，以區分獨立與衝突存取。

兩操作存取重疊 tile region，且至少一方修改選取 accumulator state 時，就建立 dependency。它涵蓋 matrix arithmetic、tile subset move、tile-clean、tile subset memory operation 間的 RAW、WAR、WAW。只有 tile dependency 解決時，controller 才給相應 identifier matrix-enable。

相容 MAC 可與 external tile access 有不同處理，因 OPE 能在內部保留並 forward intermediate partial sum，避免不必要地序列化同目標 MAC。Move 或 memory operation 則需 bank-resident state，必須等待 OPE 將衝突 pipeline-resident result drain 回 accumulator。

### Issue、完成與 retirement

Controller 將 request acceptance 與 execution eligibility 分離。已解碼操作可先由 OPE/VLSU 接受並放入 local queue；只有 vector-register 與 matrix-tile dependency 都允許時，controller 才 assert execution-enable。VAU、OPE、VLSU 以攜帶 common identifier 的 response 回報 local completion，controller 釋放 scoreboard entry、移除對較年輕操作的 dependency edge 並 retire 操作。Local completion 不是 request acceptance，也不是中間 datapath event；例如 OPE MAC 已 issue 所有 spatial beat 後，其最新結果可能仍在 FPU pipeline，必須依 accumulator-consistency protocol 才能 retire。

## Outer Product Engine（OPE）

### 總覽

OPE 實作 RISC-V Vector Matrix Extension 的算術與 accumulator 部分。Matrix configuration 由 controller 處理，tile subset memory instruction 由 VLSU 執行；OPE 執行 matrix multiply-accumulate、管理 matrix-tile state，並在 accumulator 與 VRF 間進行 tile subset move。

OPE 包含 distributed accumulator array、distributed outer-product FPU array，以及負責 request buffering、scheduling、hazard management、completion reporting 的 wrapper logic。Accumulator/FPU array 在空間上對齊 8×8 compute array。Accumulator 儲存 tile partial sum，FPU array 進行 outer-product update；本文的 FPU 專指 OPE 內 FMA、SDOTP datapath，與 VAU 的 floating-point unit 不同。

Accumulator array 與 FPU array 解耦。Accumulator 持有 bank-resident tile state，FPU pipeline 可暫存同 tile element 較新的 in-flight update。MAC 從 VRF 取得 vector operand，feedback addend 由 accumulator bank 或 matching pipeline-resident result 取得。連續操作可 forward pipeline result，避免先 writeback 再 reread；若 tile move/memory operation 需穩定值，或 forwarding 無法供應相依操作，OPE 先將相關 result 寫回 accumulator。

### 分散式 accumulator array

#### 實體組織與 tile mapping

Accumulator array 分散於 64 個 lane-local bank，對應 8×8 OPE compute array。每個 FPU lane 對齊一個 accumulator bank，因此一次 outer-product update 能平行讀取並更新一個 8×8 spatial region 的 64 個 element。每個 bank 儲存 32-bit physical accumulator word。

VME 有 16 個 logical matrix tile identifier，但每個 bank 僅四個 physical storage slot。32-bit physical word 含四個 byte：logical tile identifier 同時選擇 physical slot，且 TEW 小於 32 bit 時選擇 byte/half-word slice。TEW=32 時，mt0、mt4、mt8、mt12 分別選取 slot 0、1、2、3；TEW=16 時兩個 logical tile 可用一個 slot 的低/高 half-word；TEW=8 時最多四個 logical tile 可共用四個 byte slice。此安排保留 16 個架構 tile identifier，卻不在窄 accumulation format 中為每個 identifier 配置獨立 32-bit storage。

Logical tile 可大於 8×8 physical compute array，故以 8×8 spatial beat 分割。對 tile edge TE 與 compute-array edge CE，每 physical slot 有 (TE / CE) × (TE / CE) 個 beat；每 bank 四個 slot，故每 bank row 數為：

    4 × (TE / CE)²

TE=16、CE=8 時，每 slot 四個 beat、每 bank 16 row，總容量為 64 × 16 × 32 bit = 4 KiB。TE=32 時，每 slot 16 個 beat、每 bank 64 row，總容量為 64 × 64 × 32 bit = 16 KiB。

#### Addressing 與介面

令 (i,j) 為 output element 的 row/column。(i % CE, j % CE) 選擇 lane-local bank；其餘座標決定 spatial beat：

    beat_row     = floor(i / CE)
    beat_column  = floor(j / CE)
    spatial_beat = beat_row × (TE / CE) + beat_column

Tile identifier 選擇 physical slot，TEW 小於 32 bit 時也選擇 byte/half-word slice；bank 中的 physical row 由 slot 與 beat index 決定。同一組 physical FPU lane/bank 因而可重用於較大的 TE×TE tile，每個 beat 只存取不同 bank row。

Accumulator 有一個 internal 與兩個 external interface。Internal interface 連接 bank 與 OPE FPU array，包含 MAC feedback addend 的 read port，以及提交 FPU result 的 writeback port。FPU 讀 bank 前，可由 forwarding path 取得同 tile element 的較新 result；這是本地 FPU bypass，不是架構可見的額外 accumulator interface。

兩 external interface 分別連接向量與記憶體子系統：VRF interface 用於 VRF 與 accumulator tile 間的 tile subset move；VLSU interface 用於 accumulator tile 與 memory hierarchy 間的 tile subset memory operation。外部存取要求請求 tile 已 materialize 至 bank；若新值仍在 FPU pipeline，OPE 先 drain/writeback。所有介面共用 bank，依 physical bank、slot、beat、selected byte range、dependency state 協調。

#### Tile 與 VRF 傳輸寬度

Accumulator–VLSU tile-data port 每次傳輸一個 physical accumulator row：

    tile-row width = TE × accumulator-element width

TE=16 為 512 bit，TE=32 為 1024 bit。Tile edge 在硬體例化時固定；runtime TEW 只選擇 row 內架構可見的 byte、half-word 或 32-bit slice。double-bandwidth VLSU 每 L1 beat 傳輸 512 bit，故對齊 TE=16 row 為一個 beat，TE=32 row 需兩個 beat。TCDM bank conflict、alignment、arbitration、response latency 都可增加延遲。

VRF interface 每 port 固定 256 bit，並與 VAU 共用三讀一寫 port。完整 TE=16 row 需兩次 VRF transfer，TE=32 需四次；理想頻寬下，tile subset move 的 transfer cycle 是對應 tile memory operation 的兩倍。

### 分散式 FPU array

#### 組織、FMA 與 SDOTP

OPE 含有執行 outer-product update 的 CE×CE distributed FPU array。每個 physical FPU lane 對齊一個 lane-local accumulator bank，更新映射到 array 的 CE×CE output region 中一個 element。對一次 issued update，OPE 為兩 source operand 各供應一個 CE-element vector：a[r] 沿 row r 分發、b[c] 沿 column c 分發，lane (r,c) 計算：

    c'[r,c] = c[r,c] + a[r] × b[c]

所有 CE² lane 同時運作。CE=8 時，一次 update 最多執行 64 個 lane-local MAC，得到一個 8×8 rank-one update。

每 lane 支援 FMA 與 SIMD dot-product（SDOTP）；選擇由 SEW、TEW 關係決定。一個 MAC 表示一次乘法及其加到 partial sum 的貢獻。SEW=TEW 時使用 FMA：

    c' = c + a × b

SEW=TEW=32 時，active lane 執行 FP32×FP32+FP32→FP32；pipeline 填滿後每 cycle 一個 FP32 MAC，8×8 array 峰值為 64 FP32 MAC/cycle，即 128 FP32 FLOP/cycle。若 design-time EnableTEW16 啟用，也支援 FP16×FP16+FP16→FP16，更新 32-bit physical word 中所選 FP16 half-word，且不做 widening accumulation。預設 EnableTEW16=0，故主要使用 TEW=32。

SEW 窄於 TEW 時使用 SDOTP。支援的 widening configuration 為 SEW=16、TEW=32；一個 32-bit source word 有兩個 packed FP16：

    a = {a₁, a₀}
    b = {b₁, b₀}
    c' = c + a₀ × b₀ + a₁ × b₁

兩個 FP16 product 由兩個 internal SIMD lane 同時計算並 reduction 為一個 FP32 result。每 active SDOTP lane 每 cycle 有兩個 FP16 MAC，產生一個 FP32 accumulator update；8×8 array 峰值為 128 FP16 MAC/cycle，即 256 FP16 FLOP/cycle。兩 product 都累加到同一 widened FP32 partial sum，不是兩個獨立 destination element。FMA、SDOTP 共用 active-lane predication、destination tracking、forwarding、pipeline residency、accumulator writeback。

#### FPU pipeline、spatial interleaving 與 active-lane mask

Pipeline register 縮短 combinational path、提高頻率，但帶來 L-cycle result latency。連續 reduction step 更新同一 output element，形成 loop-carried RAW dependency；一條相依 accumulation chain 只能每 L cycle 更新一次。

Spatz OPE 依 O-POPE 原則，重用 FPU pipeline register 作隱含 accumulation buffer。每個 valid pipeline entry 保留 in-flight result，metadata 標示 destination tile、spatial beat；到達 forwarding point 後可直接作為後續 update 的 addend。若要每 cycle issue 一次 outer-product update，scheduler 至少需交錯 L 條獨立 chain，OPE 從同一 logical tile 的 spatial decomposition 取得這些 chain。

Active tm×tn region 被分成 CE×CE beat：

    Gm = ceil(tm / CE)
    Gn = ceil(tn / CE)

操作 issue Gm×Gn 個 beat。TE=16、CE=8、tm=tn=16 時有四個 quadrant C00、C01、C10、C11：

    C00 += A0 ⊗ B0
    C01 += A0 ⊗ B1
    C10 += A1 ⊗ B0
    C11 += A1 ⊗ B1

四-cycle pipeline 連續 issue 此四 beat 即有四條獨立 chain；回到 C00 時，先前結果已到 forwarding point。完整 latency-hiding 條件為 ceil(tm/CE) × ceil(tn/CE) ≥ L；full tile 時為 (TE/CE)² ≥ L。

每 beat 一律映射完整 CE×CE array。對 block (i,j)，lane (r,c) 對應 row = i × CE + r、column = j × CE + c，僅當 row < tm 且 column < tn 時 active。此比較產生隨 result 在 pipeline 前進的 activity mask，並和 tile identifier、TEW、beat index、writeback state 一同保存。Inactive lane 不執行 FMA/SDOTP、也不寫 accumulator，故 active region 外內容不變。這與 RVV vl 類似，但 inactive matrix lane 是明確抑制；tm、tn 定義 M、N 維，tk 獨立定義 reduction 維。

#### Result forwarding 與 writeback

FPU pipeline 將 arithmetic recurrence 和 physical accumulator access 解耦。Accumulator 提供 bank-resident backing storage，pipeline 保留較新的未提交 update。每個 MAC addend 選擇 destination element 的最新版本：若無較新 result，由對應 lane-local bank 讀取；若同 tile/beat result 到 forwarding point，則選 pipeline result。

有 valid FPU pipeline result 的 tile 稱為 resident tile。針對 resident tile 的連續 MAC 用 forwarding，不需 materialize 每個 intermediate partial sum。支援設定中 tk 上限為 KMAX=4；更長 reduction 以多個目標相同 tile 的 MAC instruction 表示，只要與 resident state 相容，partial sum 可跨 instruction forward。每 pipeline result 攜帶 tile identifier、TEW、spatial-beat index、active-lane mask、writeback state；bank 由 FPU lane 靜態位置決定，無須放入 metadata。

Pipeline drain 將 resident tile 的 valid result materialize 至 accumulator。MAC 改 destination tile、VRF tile move 或 VLSU tile memory operation 存取 resident tile、或相依 MAC 無法由 forwarding/bank read 取得正確 addend 時，都必須 drain。Drain 時禁止衝突操作 issue，讓 valid entry 前進至 writeback point；每 FPU lane 依 metadata 選 slot、beat、TEW slice、mask 寫回 bank。當 pipeline 不再有該 resident tile 的 valid result，blocked operation 才可繼續。

若 tile-clean discard 或 zero 覆寫 resident tile，舊 pipeline result 不再是架構必需，可 invalidated 而不需 writeback；任何讀取、保留、move、store 目前 tile 的操作皆需 writeback drain。FMA、SDOTP 的 forwarding/resident/drain/writeback protocol 相同，僅算術分解不同。Local MAC completion 與 accumulator writeback 是不同事件，controller 最後維護全域 dependency 並做 architectural retirement。

### OPE 操作類別

OPE 支援 matrix multiply-accumulate、tile-to-vector move、vector-to-tile move、tile-clean 四類操作。它們共用 distributed accumulator，但 VRF direction、accumulator access、transfer granularity、completion condition 不同。Tile subset memory operation 由 VLSU 而非 OPE wrapper 執行；但同樣經 Tile interface 存取 accumulator，目標 tile 有 resident FPU result 時必須等 state materialize 到 bank。

#### Matrix multiply-accumulate

MAC 從 VRF 讀 source operand，更新 distributed accumulator 的 destination tile。每個 issued spatial beat 消耗左右 operand 各一個 CE-element segment；CE=8 時，一個 eight 32-bit-word segment 為 256 bit，經一個 VRF read port 傳輸。tk 決定架構 operand footprint。tk=1 時：

    C' = C + A0 ⊗ B0

tk>1 時 VME operand model 另有 implicit row-stride source vector。tk=2 時：

    C' = C + A0 ⊗ B0 + A1 ⊗ B1

A0、B0 明確指定，A1、B1 為隱含 row-stride vector；controller 將四個 vector group 都記為 source dependency，故後續 write 必須排在 matrix operation 後。

FP32 operand 每個 value 已是 32 bit。對 FP16-to-FP32，vl=16 的 FP16 vector load 僅傳 256 bit，只填滿 512-bit vector register 一半，也僅用到 512-bit L1 transfer 一半；傳統 tk=2 需 A0、B0、A1、B1 四次 FP16 load，可能使 FPU 等待。

因此 tk=2 使用 packed-pair：軟體先將 reduction 方向相鄰兩個 FP16 value pack 為一個 32-bit word：

    a_packed = {a_odd, a_even}
    b_packed = {b_odd, b_even}

SDOTP 取 low/high half-word 作兩個 reduction position，產生一個 FP32 update。每 packed vector load 傳輸 16 個 32-bit element，即 512 bit，填滿完整 vector register；左右各一個 packed load 即取代傳統四個 FP16 load。這只改變 physical operand delivery；controller 仍記錄 implicit row-stride group 為架構 read dependency，以保留 RAW hazard。

#### Tile move、clean 與資源互動

Tile-to-vector move 將選取 accumulator subset 搬進 VRF。Tile Subset Specifier 選 source tile、row/column orientation、初始 subset index。OPE 將二維 coordinate 轉為 lane-local bank address，讀 physical word，擷取 TEW 選取的 byte/half-word/word slice，序列化為 256-bit VRF word。Row move 打包連續 column；column move 從 bank/beat gather。完整 physical row 在 VRF interface 上需 TE=16 的兩次或 TE=32 的四次 transfer。此操作需 committed bank-resident state；若有較新 pipeline result，先 writeback drain。Logical-zero region 可直接回傳 zero。

Vector-to-tile move 將 VRF 資料寫入 accumulator subset。它讀 256-bit VRF word，將 active vector element 映射到 tile coordinate，推導 destination bank、beat、slot、byte range。Write path 以 byte enable 保留共享 32-bit physical word 的鄰近 tile，這對 TEW=8/16 必要。Local data latch 在 VRF word 被接受後保留資料直到 accumulator write 完成，將 VRF read completion 與 bank availability 解耦。寫入清除相應 logical-zero marker，並使新值對後續 FPU/move/memory 可見。

Tile-clean 不讀 VRF、不傳明確 operand payload，支援 tile-zero 與 accumulator-discard。Tile-zero 以 physical slot、beat、byte range 將 region 標記 logical zero，後續 FPU/move/memory read 以 zero 取代，避免逐 bank 寫 zero 的多 cycle sweep。後續 vector-to-tile move/FPU write 清除 marker。Accumulator-discard 在內容不再需要時使既有 state 無效；只有 active MAC、move、memory、drain 不再依賴它時才可執行。

| 操作類別 | 來源 | 目的地 | 主要資源 |
| --- | --- | --- | --- |
| Matrix multiply-accumulate | VRF operand、accumulator addend | FPU pipeline 或 accumulator | VRF read port、FPU array、accumulator |
| Tile-to-vector move | Accumulator | VRF | Accumulator read path、VRF write port |
| Vector-to-tile move | VRF | Accumulator | VRF read port、accumulator write path |
| Tile clean | Accumulator metadata/storage | Accumulator state | Zero metadata、drain/flush control |

只有資源存取不衝突時，操作可獨立進行。Wrapper 依 tile identity、spatial beat、byte range、pipeline residency、controller dependency state 協調。

### OPE wrapper

OPE wrapper 接收 controller 解碼的 VME request，並將 request acceptance 與 execution 解耦。每 request 帶有 instruction identifier、vector/matrix configuration snapshot、source/destination 資訊及適用的 tile-subset metadata；snapshot 確保後續 configuration change 不改變已緩衝操作的解讀。

MAC request 進入四 entry、non-fall-through stream FIFO；tile-to-vector、vector-to-tile、tile-clean 使用專屬 spill-register queue。MAC queue 可在 vector load、tile-memory transfer 或 accumulator access 延遲後續 operand 時保留多個 ready arithmetic operation。FPU datapath 釋放後，已 buffered MAC 可直接 issue，無須等下一個 controller request。Class-specific spill register 吸收短暫反壓，避免某一類暫不可用就阻塞其他 request acceptance。

Wrapper 仲裁 queue head，僅在 controller execution-enable assert 且 target accumulator state 可安全存取時授予執行。Hazard check 涵蓋 target tile、beat、byte range、resident FPU result、pending accumulator write、logical-zero state、衝突 move/clean。衝突 request 等到 result 被 forward、writeback 或由 clean invalidated。

Completion 與 acceptance/execution 分離。操作到達 local completion point 後，wrapper 將 identifier 放入 response spill register，再由 response arbiter 送到 controller。MAC 即使已 issue 所有 beat，最新 result 仍可能在 FPU pipeline；只有 controller 收到並依全域 dependency state 處理 response 後，才做 architectural retirement。

## Vector Load Store Unit（VLSU）

Tile subset memory operation 由 VLSU 執行，透過 local TCDM 與 distributed accumulator array 傳輸選取 tile subset，不經 VRF。故 matrix tile 有兩條 data path：tile subset move 經共用 VRF；tile subset memory operation 經獨立 VLSU Tile path。

### Request buffering 與 address generation

VLSU 將 decoded tile-memory request 放入四 entry request FIFO。Request 含 memory base address、direction、captured matrix configuration、tile identifier、Tile Subset Specifier、instruction identifier。FIFO 將 acceptance/execution 解耦，較早 transfer 等 accumulator access、TCDM availability、memory response 時，獨立操作仍可前進；FIFO 滿時才傳播反壓。

VLSU 由 Tile Subset Specifier 推導 Tile-interface access。Specifier 指定 tile、row/column orientation、初始 subset index；VLSU 結合 vector length、vector start、active tile dimension 產生 transfer sequence、memory address。Row request 存取選取 tile row，必要時跨連續 physical chunk；column request 走訪構成 logical column 的 physical accumulator row，對 store gather、對 load scatter。這些 traversal 保持 tile subset operation 的架構 row/column 語意。

### Tile 介面與 TCDM 傳輸粒度

Tile interface 與 VRF-facing move path 不同，不占用 shared VAU–OPE VRF port；tile memory operation 因而獨立於 VRF arbitration，但仍受 Tile-interface、accumulator dependency、TCDM availability 限制。它一次傳輸一個 physical row：

    tile-row width = TE × accumulator element width

TE=16 使用 512-bit Tile row，TE=32 使用 1024-bit Tile row；runtime configuration 只選擇 physical representation 中的 byte、half-word、word slice。

在 double-bandwidth、單一 active Spatz core configuration，VLSU 每 cycle 可 issue 八個 64-bit TCDM request，peak aggregate 為 512 bit/cycle。對齊 TE=16 row 對應一個 512-bit beat，TE=32 row 為兩個 beat。實際 cycle 可能因 row/column 數、alignment、TCDM bank conflict、其他 requester arbitration、memory-response latency 增加。四 entry FIFO 吸收短暫變動 latency。Load 時 VLSU 由 TCDM 接收 Tile data 後經 Tile interface 寫入 accumulator；store 時先由 Tile interface 取資料，再送出 TCDM write request。

### 與 OPE 的協調

VLSU 與 OPE 共用 distributed accumulator，但職責不同。VLSU 負責 address generation、TCDM request scheduling、response handling、Tile-data movement；OPE 維護仍在 FPU pipeline 的 partial sum 一致性。VLSU 存取 tile 前，所需 state 必須是 bank-resident。目標 tile 的新 result 若仍在 FPU pipeline，OPE 必須先 writeback drain，再授予 external Tile access。這避免 memory read 看到 stale partial sum，也避免後續 pipeline writeback 覆寫較新的 memory-loaded value。

Tile-memory request 因而可能在 OPE drain 衝突 resident tile 時保持 queued。state materialize 到 bank 後，VLSU 執行 Tile/TCDM transfer；request 完成後回傳 common identifier 的 completion response，controller 清除 dependency 並按全域 vector–matrix ordering rule 允許 retirement。完整 TE=16 row 經 VRF path 需兩次 transfer、經 VLSU/TCDM path 僅一個 beat；TE=32 分別為四次與兩個 beat。

## Instruction supply：iCache 與 iBuffer

Spatz cluster 以 elaboration-time parameter UseInstructionBuffer 選擇兩個互斥 instruction-supply implementation。關閉時 core 經 instruction-cache hierarchy fetch instruction；開啟時用 compact instruction buffer 取代 cache hierarchy。兩者都經 instruction-side AXI path 從 memory system 擷取 data，但在 capacity、miss behavior、control complexity、storage cost 上取捨不同。

Instruction-cache configuration 是傳統 cache hierarchy，適合超過小型 loop buffer 的 instruction working set。它保存較大 instruction footprint，並在多個 code region 間利用 temporal/spatial locality；對 unrolled kernel、較大 application、重訪多個 instruction region 的 control flow 有利，但 cache lookup、tag storage、replacement state、refill control 增加 area/control overhead。

Instruction buffer 是供 compact、重複 code region 使用的低複雜度替代方案。現行實作每 fetch port 有兩個獨立 tag 的 buffer half：一半供 core fetch，另一半可 refill/prefetch。兩 half 共用一筆 AXI refill transaction；多個 fetch port 的 demand miss 由 round-robin 選擇。當目前 half hit，而下一 half 缺失或屬不同 instruction region 時，可 prefetch 下一 half。此 two-half organization 讓目前 code region 執行與下一 region 準備重疊，適合 working set 可放入 buffer 且 instruction access 可預測、連續的小 loop。相對 iCache，它降低 storage/control overhead，但容量較小，對大型或不規則 footprint 的容忍度較低。

這影響 matrix-kernel scheduling。Rolled kernel 的 instruction footprint 較小，重複執行 compact loop body，適合 iBuffer。Unrolled kernel 減少 loop-control overhead，可能改善 compute scheduling，但較大 static code size 會增加 cold miss、refill traffic。取捨取決於 execution-overhead 降低是否超過 instruction-supply subsystem 壓力增加。

Packed FP16-to-FP32 kernel 也影響此取捨。兩個 FP16 reduction value pack 成一個 32-bit operand，可減少固定 FP16 computation 所需 vector load、matrix MAC operation，降低 dynamic instruction count，並可能縮小 static footprint。這可減少 cold miss、instruction-fetch stall，改善任一 instruction-supply option 的效果。實驗因此比較 rolled/unrolled、FP32/packed FP16、不同 tile-edge configuration 下的 iCache 與 iBuffer 行為。
